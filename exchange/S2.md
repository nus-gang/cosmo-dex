# S2-C Rust 서비스 (검토 후보)

이 브랜치는 [NUS-38](/NUS/issues/NUS-38)의 로컬 구성요소 구현이다. 승인 계약
[NUS-36](/NUS/issues/NUS-36) head `3571c3a331a169a8eef231aad14f7816908dd2c5`를 소비한다.
실제 체인 snapshot의 기준은 [NUS-37](/NUS/issues/NUS-37) head
`7ce952475b4985096344d713467208722b5e7693`이다. REST/RPC 수집과 브라우저 연결은
[NUS-39](/NUS/issues/NUS-39), 통합 실행은 [NUS-41](/NUS/issues/NUS-41)의 인수 범위다.
이 문서는 main 배포 또는 전체 S2 PASS를 뜻하지 않는다.

## 빌드와 실행

Rust 1.92.0, `exchange/Cargo.lock`을 사용한다. OrderBook-rs `=0.13.1`
(MIT, default-features=false), fips204 `=0.4.6`(MIT OR Apache-2.0)은 기존 pin 그대로다.
OrderBook 라이선스와 태그 증거는 `evidence/licenses/` 및 기존 `README.md`에 있다.

```sh
cargo build --locked --manifest-path exchange/Cargo.toml --bin exchange-s2
exchange/target/debug/exchange-s2 create MANIFEST JOURNAL BOOTSTRAP
exchange/target/debug/exchange-s2 open MANIFEST JOURNAL
```

`MANIFEST`는 신뢰하는 통합 실행자가 생성하는 JSON 파일이다. 필수 필드:

```json
{
  "context": "ChainSnapshot.body.context 객체",
  "market": "ChainSnapshot.body.market 객체",
  "owners": ["raw20 canonical base64 첫 owner", "둘째 owner"],
  "supplies": ["DEVBASE genesis 총 atoms", "DEVQUOTE genesis 총 atoms"],
  "bootstrap_snapshot_id": "최초 보존 ChainSnapshot의 64자리 hex hash"
}
```

위 두 설명 문자열은 실제 객체로 대체한다. owners는 raw bytes 오름차순이다.
`contract_hash`=`2e103517c344f21c2b97fbe7e977f0e614c32c704b0f54978c5bb1fb3ae6ab0f`,
`config_hash`=`70281595d471947a56d9bf8a97553dd388a85b107c215a95cc6f34ea9f5f321f`,
chain=`nus-s2-dev-1`을 요구한다. genesis/owners/supplies는 실행자가 실제 B genesis와
대조해 고정한다. 요청 body에서 얻은 값을 manifest로 승격하지 않는다.
`BOOTSTRAP`은 해당 ID의 검증 가능한 최초 snapshot JSON이다. `create`는 없는
journal 디렉터리만 생성한다. S1과 다른 S2 디렉터리·genesis를 사용한다.
`open`은 고정 bootstrap과 전체 WAL의 입력·결과·상태 hash를 다시 계산한다.

stdout은 아래 응답 프레임 전용, stderr는 고정 오류 코드/OS 오류다. 부모가 stdin/stdout
전용 pipe를 소유하고 프로세스 생명주기를 관리한다. 이 바이너리는 포트를 열지 않는다.
서명 검증·세션·명령 순서·영속 상태는 Rust 프로세스 한 writer에서 처리한다.
기동 실패는 nonzero이며 자동 새 원장 생성·WAL 삭제·마이그레이션을 수행하지 않는다.

## Settlement transport 인계

stdin 한 줄에 JSON 한 객체, 끝에 LF를 보낸다. 100,000B control 상한이며 불완전/초과
프레임은 프로세스를 종료한다. 응답은 `{"http_status":"200","body":{...}}` 한 줄이다.
동시에 명령을 pipe에 섞지 않고 부모가 요청→응답을 직렬화한다. EOF/pipe 단절로 응답을
못 받았다면 `SUBMISSION_UNKNOWN`으로 표시하고 같은 bytes/ID로 조회·재시도한다.

브라우저에서 받은 요청은 다음 **request envelope만** 부모가 구성한다. 브라우저 JSON을
control message 그대로 전달하면 안 된다. body_base64는 원 HTTP body의 padded base64다.

```json
{"op":"request","method":"GET","path":"/s2/status","origin":null,"authorization":null,"body_base64":""}
```

`path`는 계약의 `/s2/*` 경로와 query다. `/s2/network`, `/s2/status`, `/s2/book`은 공개이고,
나머지는 실제 WalletChallenge 서명 세션으로 owner를 결정한다. 챌린지는
`POST /s2/auth/challenges` body `{owner,origin,audience:"exchange-api"}`,
응답 `{wire_base64}`다. `POST /s2/auth/sessions` body는
`{wire_base64,signature_base64}`, 응답은 token/owner/origin/audience/genesis_hash/expiry_time이다.
세션 TTL 300초, nonce TTL 120초, Origin은 profile 두 loopback 값의 정확 일치만 허용한다.
`POST /s2/auth/logout`은 빈 body로 현재 세션을 폐기한다. 계정 전환 시 부모/Wallet은 이전
세션을 로그아웃하고 응답 generation을 폐기한다. 재시작 뒤 토큰은 무효다.
개인 조회에도 Origin과 `Authorization: Bearer ...`를 그대로 전달한다.

Order/Cancel body는 승인된 SignedCommand(context/wire_base64/signature_base64),
출금 prepare/abort는 LocalAction(request_id)다. 새 성공은 201, 같은 receipt 재조회는 200,
정책 거절은 계약 HTTP code와 영속 REJECTED receipt다. 원 receipt와 최신 상태는 분리된다.
`GET /s2/me/orders/{id}?epoch=...`의 `{order,receipt}` 또는 `/s2/me`로 최신 상태를 조회한다.
ORDER command 조회는 epoch 필수이며 타인의 ID와 미존재 ID는 같은 NOT_FOUND_AT_SEQ다.
개인 query의 임의 owner는 403이다. `cursor`가 속한 seq가 바뀌면 409로 전체 재조회한다.

부모의 신뢰 RPC 경로만 아래 control을 보낼 수 있다. 브라우저 endpoint로 노출하지 않는다.

```json
{"op":"observe","snapshot":"검증할 ChainSnapshot 객체","cursor_height":"101","received_at_unix_ms":"1790956680000","query_latency_ms":"1","catching_up":false}
{"op":"rpc_failed"}
```

Rust는 context/hash/등록키/보존식·연속 높이를 검증한다. 부모는 raw ABCI 및 같은 H의
header/hash/time을 대조하고 증거를 저장하며 H+1부터 빈 블록도 빠짐없이 공급한다.
조회 단절/timeout 때 `rpc_failed`를 보내고 누락된 H를 건너뛰지 않는다. 시작/재시작은
CATCHING_UP으로 닫히며 재관측이 필요하다. block/조회 age >5000ms도 닫힌다.
시간은 서버가 취하고 caller의 `now`를 요청 파라미터로 받지 않는다.

HTTP bind/CORS/timeout/body 상한은 NUS-39 adapter가 적용한다: loopback bind,
exact Origin allowlist, wildcard 금지, browser raw body 16384B 상한, 공개/개인 캐시 분리,
계정 전환/역순 응답 폐기. Rust도 body 상한·Origin·등록 서명·owner를 재검증한다.
Status.revision은 영속 예약된 응답 번호, LedgerView.revision/stream_seq는 committed command_seq다.
Book content_hash는 동일 seq에서 불변이고 live 신선도는 Status로 제공한다.

## 경제 상태와 내구성

C/R/D/P/A를 정수로 유지한다. A=C−R−D, P는 재주문/출금에 사용할 수 없다.
부분 체결의 최악 매수 입력 D는 가격 개선분도 유지한다. 취소/IOC는 미체결 R만 푼다.
OrderBook callback과 반환값을 동일한 ordered outcome으로 검산하며 IOC Err 뒤 callback도
한 번만 반영한다. 매 명령마다 비공개 주문장을 재구성하고 라이브러리 랜덤 ID/시계는
지속 상태에 사용하지 않는다. 성능 최적화된 운영 엔진이 아니다.

snapshot epoch 변화는 두 owner의 pending 의존 성분을 정정하고 D/P/잠정 fee를 역분개한다.
원 receipt와 lifetime filled는 보존한다. 출금 준비는 잔량을 취소·동결하고 D/P가 남으면
UNSETTLED_HOLD다. 실제 출금 권한은 기존 DIRECT TX에 있다. outbox는 HELD_S2,
submission_enabled=false이며 서비스·재생 코드에 외부 발송 경로가 없다.

후보 계산 → 최대 정정 인코딩 길이 사전 검사 → WAL fsync → marker temp fsync/rename/
directory fsync → 상태/receipt 공개 순서다. bootstrap은 별도 불변 파일이며 각 record의
state_json은 전체 상태 snapshot이다. 별도 증분 checkpoint/GC는 사용하지 않는다.
복구는 전체 signed/internal 명령을 저장한 관측/시각으로 재실행하고 결과/상태를 대조한다.
다른 프로세스 writer는 OS lock으로 차단한다. 불확실 tail·손상은 원본과 evidence 사본을
보존하며 성공 기동하지 않는다. 운영자가 원인을 조사하고 보존본과 외부 ACK를 대조해야 한다.

용량은 전체 이력을 포함해 mutable 정수의 최대 자릿수, Text 128B, 가장 긴 enum과 bool,
base64 반올림을 적용한 실제 인코딩 상한으로 계산한다. 일반 record와 최대 정정 record가
각각 16MiB 이하여야 한다. 16MiB+72+8192B 별도 reserve를 write/fsync하고 정정만 소비한다.
재확보 실패 후 새 접수는 닫는다. commit이 시작된 뒤 IO/재확보 실패는 UNKNOWN이며
이미 commit된 정정은 재시작 재생으로 복원할 수 있다. 보유 기록을 잘라서 공간을 만들지 않는다.

## 검증과 제한

```sh
cargo test --locked --manifest-path exchange/Cargo.toml
cargo test --locked --manifest-path exchange/Cargo.toml --features fault-injection --test s2_process
cargo clippy --locked --manifest-path exchange/Cargo.toml --all-targets --all-features -- -D warnings
```

`fault-injection`은 실험 바이너리 전용 feature다. 기본 빌드는 fault 환경변수를 읽지 않는다.
시험 harness는 signed append/정정의 before/partial/WAL/marker/rename/commit 강제 종료,
ENOSPC 오류 주입, 두 번째 writer, ACK 뒤 kill·재시작, 응답 유실 재시도, 손상 원본 보존을 검사한다.
호스트 디스크를 실제로 가득 채우는 시험은 하지 않는다. `S2_PROCESS_EVIDENCE` 디렉터리,
`S2_CAPACITY_EVIDENCE` JSON, `S2_RUNTIME_SCHEMA_OUTPUT` JSON 환경변수로 원시 결과를 저장한다.
시험 파일은 Paperclip run scratch 또는 일반 실행의 OS temp에서 생성한다.

로컬 fsync는 장애 영역 복제가 아니다. 프로세스 종료는 전원 손실과 다르며 macOS
F_FULLFSYNC/파일시스템별 ENOSPC 물리 보장은 미검증이다. WAL+marker를 동시에 과거로
돌리면 로컬만으로 탐지할 수 없어 외부 ACK ledger와 seq/hash를 대조한다. 시험도 이 제한을
명시적으로 재현한다. 실제 체인 예치 기반 REST/브라우저·4검증인 통합은 D/F/H/J에서
검증한다. 처리량·finalized TX/s 목표 달성, 분산 내구성 T08/T10, 온체인 정산 또는 전체
S2 PASS를 주장하지 않는다.
