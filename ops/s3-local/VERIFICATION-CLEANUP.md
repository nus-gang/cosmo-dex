# 검증 종료 시 디스크 정리

2026-10-07 · NUS-73 · SRE

근거: [디스크 정리 인계](/NUS/issues/NUS-73#comment-1416a179-4f9f-4319-bb35-9fc0141c2670). 각 검증 종료 절차에 적용하며 새 업무나 타이머를 만들지 않는다.

1. 원시 입력·출력·최초 실패·보정 결과·명령·버전·SHA256을 증거 디렉터리에 보존한다. 비밀키·토큰은 첨부하지 않는다.
2. 전달 bundle을 Paperclip attachment와 artifact work product로 게시하고 성공 응답과 접근 경로를 확인한다. 게시가 실패하거나 불확실하면 관련 원본과 임시 사본을 보존한다.
3. 사용이 끝난 **자기 소유** 빌드 캐시·임시 파일을 정확한 경로 목록으로 고른다. 활성 프로세스의 cwd/argv/open files, 관리 runtime 등록 참조, 심볼릭 링크 및 후속 재현 필요성을 대조한다. 불명확한 항목은 삭제하지 않는다. 타 담당자의 정리를 중복 수행하지 않는다.
4. 대상별 logical bytes와 allocated bytes 또는 `du -sk` 값을 삭제 전에 기록한다. 측정 단위와 시각을 명시한다. source/Git·승인 후보 binary/web/manifest·home/genesis·키·원장·검증 증거·공유 의존성은 보존한다. 현재 S3 캐시는 다음 빌드에서 사용하므로 보존한다.
5. 게시 확인 후 확정한 개별 대상만 삭제한다. 광역 glob, 전체 worktrees 삭제, symlink 추적 삭제는 사용하지 않는다. 이번 run의 임시 파일은 PAPERCLIP_RUN_SCRATCH_DIR에 만들며 원시 근거는 run 종료 전에 게시한다.
6. 같은 방식으로 전후 용량과 대상 수·삭제량·실패/보존 이유를 기록한다. 동시 작업에 영향받는 전체 디스크 가용량 차이를 자기 정리 효과로 보고하지 않는다. 대상이 없으면 삭제 0 bytes와 보존 이유를 남긴다.

종료 댓글에는 검증 결과와 artifact 링크, 정리 전후 값, 보존 항목, 미완료 실행/승인 상태를 함께 남긴다. 디스크 정리는 runtime 승인이나 서비스 종료/lock 해제 증명을 대체하지 않는다.

## 이번 요청 처리

이번 실행은 종료 절차 문서화와 용량 관측이다. 제품 build/test/서비스 실행은 수행하지 않았다. 현재 S3 전체·NUS-70/71/56 캐시·공유 web node_modules·소스/Git/home/키/원장/증거는 보존한다. CEO가 맡은 과거 target/cache 정리는 수행하거나 완료를 대신 주장하지 않는다. 삭제 대상으로 확정된 파일은 없으며 삭제량은 0 bytes다.
